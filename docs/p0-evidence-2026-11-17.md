## Implemented

- Explicit quit intent. An unowned `ExitRequested` cannot begin monitoring shutdown.
  Closing a dashboard hides it; only the owned Quit action starts producer stop and storage flush.
- Serialized exit phases: Running -> Flushing -> AwaitingAcknowledgement -> Finalizing -> Ready.
  Ordinary or delayed Quit cannot acknowledge a failed flush, bypass log draining, or erase
  internal finalization intent. Failed flush requires the distinct enabled discard action.
- Diagnostics finalization runs off the UI thread with a 500-ms wait budget. Native collector
  joins are still inherited and are not claimed to have a new hard shutdown deadline.
- Single-instance plugin first in registration order, plus a retained OS file lease per data
  directory before any workers/logger start. This closes the plugin's startup ownership race.
  Windows begin hidden; foreground launch shows them only after host ownership/setup.
- macOS owned application Quit/Close menu actions share the explicit policy. Native macOS
  behavior still needs acceptance; cross-platform Tauri menu APIs were typechecked on Windows.
- A nonblocking 128-event queue with UTF-8-safe bounded messages; two event files of at most
  256 KiB each and one fatal file of at most 4096 bytes. Startup also bounds existing oversized files.
  Queue saturation/errors expose drops and status, not collector failures. No per-tick file logs.
- In-flight admission tracking prevents a successful drain from missing an admitted late sender.
  The panic hook preserves the previous hook. Its best-effort fatal write is bounded in bytes,
  not in wall-clock time; OS abort/kill can still lose diagnostics.
- Three fixed worker health slots (system/processes/storage), heartbeats, transition warnings,
  panic status and stale-generation protection. `get_runtime_health` exposes these plus logging
  status and ignored exit requests; production UI integration is deferred.
- Read-only Windows whole-process-tree CPU/RAM sampler requiring an explicit running Monitor PID.
  Partial access yields unavailable totals, not fabricated zero. It neither starts nor stops the app.

History format, collectors, ETW semantics and native taskbar placement were not redesigned in P0.
The existing fixed history file remains unchanged. CSV exports are not part of storage bounds.
